# パネル「表示・非表示」の現状バグまとめ

## 実装の概要（現状）

- **非表示**: パネルを「閉じる」のではなく、スタックごと `parent.removeChild(stack, true)` でレイアウトから外し、`hiddenPanels` に退避している（中身を保持したいため）。
- **表示**: 退避済みなら `target.addChild(saved.stack, index)` で元の親（または親が消えていれば row）に追加。なければ `layout.newComponent()` で新規追加。

---

## 再現シナリオ（左縦カラムに プルダウン目次・スニペット・変数 があるとき）

**前提**: ハンバーガーメニュー「ウィンドウ」で、プルダウン目次・スニペット・変数が**同じ縦の 1 本のカラム**に並んでいるレイアウト。

1. **「プルダウン目次を表示」を押す（表示にしたい）**
   - **起きること**: プルダウン目次は消えず、**変数パネルが半分ほど消える**（表示したいはずのプルダウン目次が正しく復帰していない）。
2. **もう一度「プルダウン目次を表示」にチェックを入れる**
   - **起きること**: 特に変化なし（何回押しても動きがない）。
3. **何回か押し続ける**
   - **起きること**: 真ん中にあった**エディタがプルダウン目次に切り替わる**。**2 つ目のプルダウン目次**が生成されるが、**中身は空**。

**他のパネル**（スニペット・変数・エディタ・プレビューなど）の表示・非表示でも同様のことが起きる。

- **消したいパネルが消えない**（代わりに別のパネルが欠ける・半分消える）
- **同じ種類のパネルが 2 つになる**（片方は中身が空）
- **元のレイアウトに戻せない**
- 操作を重ねるほど**レイアウトが崩れていく**

---

## バグ一覧（整理）

### 1. 「表示」を押しても意図したパネルが復帰せず、別のパネルが欠ける

**現象**
- 「プルダウン目次を表示」を押すと、**プルダウン目次は消えたまま**で、**変数パネルが半分ほど消える**（左縦カラムに プルダウン目次・スニペット・変数 があるとき）。
- 表示したいパネルが正しい位置に戻らず、別のパネル（変数・プレビューなど）の表示が欠ける。

**想定原因**  
退避したスタックを `addChild` する先（親または row）や index が、Golden Layout 側の「列が 1 子で replace される」挙動のあとでずれており、**誤った位置に挿入されている**ため。

---

### 2. 「表示」を繰り返すと、同じ種類のパネルが 2 つになる（片方は中身が空）

**現象**
- 「プルダウン目次を表示」を何回か押すと、**真ん中にあったエディタがプルダウン目次に切り替わる**。**2 つ目のプルダウン目次**ができるが**中身は空**。
- 変数・スニペットなどでも、同種パネルが 2 つになることがある。

**想定原因**
- 退避スタックの復帰（`addChild`）が失敗または誤った状態になり、**`layout.newComponent()` が呼ばれて新規パネルが 1 つ追加される**。
- その結果「退避した 1 つ ＋ 新規 1 つ」で同じ種類のパネルが 2 つになる。新規は中身が空。

---

### 3. 消したいパネルが消えず、元に戻せない

**現象**
- 非表示にしたいパネルを「非表示」にしても、**そのパネルは消えず**、代わりに別のパネルが欠けたり半分消えたりする。
- 「表示」にしても、**元のレイアウトや状態に戻らない**。操作を重ねるほどレイアウトが崩れる。

**想定原因**
- 非表示時に `removeChild(stack, true)` の対象や、列の replace のタイミングで、**意図したスタック以外が動いている／参照がずれている**可能性。
- 復帰時に「列」がすでに消えているため row に add され、**左が「1 本の列」ではなく「スタックが横並び」**になり、元の並びに戻らない。

---

### 4. 根本：Golden Layout の「列が 1 子で replace される」挙動

- 縦 1 本の**列（Column）**の中から 1 つスタックを外すと、**列の子が 1 つだけ残った時点で「列そのもの」が消え**、残り 1 子が親（Row）の直下に置き換わる（`replaceChild`）。
- 退避時に保存した「親（列）」が DOM 上に残らなくなるため、**表示時の復帰先がずれ、誤った位置に add されたり、newComponent にフォールバックしたりする**。

---

## 根本原因の整理（上記の現象を引き起こしている要因）

| 要因 | 内容 |
|------|------|
| Golden Layout の replaceChild | 列の子が 1 つになった瞬間、列が消えてその 1 子が row の直下に置き換わる。退避したスタックの「元の親」が DOM 上に残らない。 |
| 復帰先の選択 | 親が消えているときは row に add するしかなく、結果として「列」構造が失われ、レイアウトが変わる。 |
| 中身保持 vs レイアウト保持 | 「閉じずに退避して中身を保持」と「元のレイアウト（列・位置）を保持」を両立するには、replace 後の新しい構造を正しく追うか、replace が起きないようにする必要がある。 |

---

## 今後の対応の方向性（メモ）

1. **退避しない方式に戻す**  
   `item.close()` と `newComponent()` のみにすると、レイアウト崩れ・二重表示は起きにくいが、**非表示→表示で中身は必ず空**になる。

2. **退避するが「列」を維持する**  
   列の子が 1 つになる前に、退避用の「ダミー」スタックを列に残すなどして、Golden Layout に replace させない。実装難易度・GL の仕様との相性の確認が必要。

3. **復帰時に列を再構築する**  
   親が消えているとき、`row.addChild(stack, rowIndex)` の代わりに「新しい Column を作り、その中に退避スタックを add し、その Column を row の rowIndex に add」する。復帰位置は近づくが、GL の API で「新しい Column」を明示的に作れるか要確認。

4. **非表示を「閉じる」ではなく「表示だけ隠す」**  
   DOM からは外さず、該当スタックの要素に `display: none` を付け、サイズを 0 にするなどしてレイアウト上も占めないようにする。構造は変わらないのでレイアウト崩れは出にくいが、GL の size 制御と両立できるか要検証。  
   → **実装済み（要動作確認）**: `closePanel` で `stack.size = 0` と `stack.element.style.display = 'none'` を設定し、`addPanel` で size と display を復元。レイアウトから外さないため replace が発生しない。

---

*このドキュメントは、パネル表示・非表示の不具合対応のための整理です。*
